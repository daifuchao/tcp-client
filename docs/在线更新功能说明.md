# 在线更新功能说明（从无到有）

本文梳理本项目「在线升级 / 差量更新 / 版本回退」相关代码与配置，便于接手或对照实现。

---

## 1. 能力概览

| 能力 | 说明 |
| --- | --- |
| 检查更新 | 读 OSS 上 `latest.yml`，与本地 `package.json` 版本比较 |
| 下载更新 | 优先 **nsis-web 差量**（`.nsis.7z` + blockmap），失败再整包 |
| 安装并重启 | `electron-updater.quitAndInstall` |
| 版本回退 | 探测/列出更低版本完整 `Setup`，下载后拉起安装程序 |
| 更新地址可配 | 设置页可改，写入 AppData `config.json` |

默认更新根地址：

```text
https://bnspic.oss-cn-guangzhou.aliyuncs.com/tcp-server-tool
```

> **注意：该 URL 不要带末尾 `/`。** Web 安装器会拼成 `{url}/{文件名}`；若写成 `.../tool/` 会变成 `.../tool//xxx.7z` 导致 404。


## 3. 演进路径（从无到有）

### 阶段 A：基础在线升级

1. 安装 `electron-updater`，`autoDownload = false`（由用户点「下载」）。
2. `package.json` → `build.publish` 配 generic OSS 地址；`win.target = nsis`；`nsis.differentialPackage = true`（生成 `.blockmap`）。
3. 新增 `electron/updater.cjs`：`setFeedURL` + `checkForUpdates` / `downloadUpdate` / `quitAndInstall`，状态经 `webContents.send('update:status')` 推到渲染进程。
4. `main.cjs` 注册 IPC：`update:status|check|download|install`；配置里增加 `updateUrl`。
5. `preload.cjs` 暴露 `checkUpdate` / `downloadUpdate` / `installUpdate` / `onUpdateStatus`。
6. 设置页增加：更新地址、检查更新、下载、安装并重启。

此时客户端流程：

```text
检查更新 → 发现新版本 → 下载（可能整包 Setup）→ 安装并重启
```

### 阶段 B：打包自增版本 + 抗文件锁

- `scripts/pack.cjs`：`npm version patch` → `vite build` → `electron-builder` → `versions.json`。
- `win-unpacked` 被占用时，自动改用 `release-pack/` 或 `release-pack-<时间戳>/`。

### 阶段 C：差量更新（nsis-web）

普通 NSIS 的 blockmap 差量常因压缩效果差、或 OSS 不支持 multipart Range，而回退成整包下载。

改为同时打两种包：

| 产物 | 用途 |
| --- | --- |
| `*-Setup-*.exe` | 离线完整安装 / 回退 |
| `*-WebSetup-*.exe` + `*-x64.nsis.7z` | 在线更新（差量主体是 7z） |

要点：

- `win.target`：`nsis` + `nsis-web`
- `nsisWeb.differentialPackage: true`
- `nsisWeb.appPackageUrl`：**无末尾 `/`**
- `publish.url`：**无末尾 `/`**
- 客户端：`useMultipleRangeRequest: false`（阿里云 OSS）
- 打包后把 `nsis-web/` 下的 `latest.yml`、WebSetup、`.7z` **提升到输出根目录**（覆盖仅含完整 Setup 的 `latest.yml`），保证根目录 `latest.yml` 含 `packages:`

### 阶段 D：版本回退

- `listVersions`：读 `versions.json`（可选）+ `latest.yml`，再 **HEAD 探测** 历史 `*-Setup-x.y.z.exe`
- `rollbackToVersion`：下载完整 Setup → `spawn(setup, ['--updated'])` → `app.quit()`
- UI：回退版本下拉 +「回退并安装」
- 打包生成/合并 `versions.json`（建议一并上传 OSS）

## 4. 核心代码说明

### 4.1 `package.json`（构建与发布）

关键字段：

```json
{
  "dependencies": {
    "electron-updater": "^6.8.11"
  },
  "build": {
    "publish": [{
      "provider": "generic",
      "url": "https://bnspic.oss-cn-guangzhou.aliyuncs.com/tcp-server-tool"
    }],
    "win": {
      "target": [
        { "target": "nsis", "arch": ["x64"] },
        { "target": "nsis-web", "arch": ["x64"] }
      ]
    },
    "nsis": {
      "differentialPackage": true,
      "artifactName": "${productName}-Setup-${version}.${ext}"
    },
    "nsisWeb": {
      "differentialPackage": true,
      "artifactName": "${productName}-WebSetup-${version}.${ext}",
      "appPackageUrl": "https://bnspic.oss-cn-guangzhou.aliyuncs.com/tcp-server-tool"
    }
  },
  "scripts": {
    "pack": "node scripts/pack.cjs"
  }
}
```

### 4.2 `electron/updater.cjs`（主进程更新逻辑）

初始化要点：

```js
autoUpdater.autoDownload = false
autoUpdater.autoInstallOnAppQuit = true
autoUpdater.allowDowngrade = true
autoUpdater.disableDifferentialDownload = false
autoUpdater.disableWebInstaller = false
```

Feed（去掉末尾 `/`，并关闭多段 Range）：

```js
function applyFeedUrl(url) {
  const u = normalizeUpdateUrl(url) // trim + 去掉末尾 /
  autoUpdater.setFeedURL({
    provider: 'generic',
    url: u,
    useMultipleRangeRequest: false
  })
}
```

对外能力：

| 方法 | 作用 |
| --- | --- |
| `checkForUpdates` | `autoUpdater.checkForUpdates()` |
| `downloadUpdate` | `autoUpdater.downloadUpdate()`（差量优先） |
| `quitAndInstall` | 安装并重启 |
| `listVersions` | `versions.json` + `latest.yml` + HEAD 探测 Setup |
| `rollbackToVersion` | 下完整 Setup 并拉起安装 |

状态推送：`mainWindow.webContents.send('update:status', status)`  
字段含：`state` / `message` / `version` / `progress` / `error` / `currentVersion`。

### 4.3 `electron/main.cjs`（IPC 与配置）

```js
const updater = require('./updater.cjs')
const DEFAULT_UPDATE_URL = 'https://bnspic.oss-cn-guangzhou.aliyuncs.com/tcp-server-tool/'

// 创建默认字段含 updateUrl
// createWindow 后：
updater.setMainWindow(win)
updater.applyFeedUrl(data.updateUrl)

ipcMain.handle('update:status', ...)
ipcMain.handle('update:check', ...)
ipcMain.handle('update:download', ...)
ipcMain.handle('update:install', ...)
ipcMain.handle('update:listVersions', ...)  // 开发模式也可拉列表，便于调试
ipcMain.handle('update:rollback', ...)
```

开发模式：`check/download/install/rollback` 仍会提示「请使用打包安装版」；`listVersions` 允许在开发环境探测列表。

### 4.4 `electron/preload.cjs`

```js
updateStatus: () => ipcRenderer.invoke('update:status'),
checkUpdate: (updateUrl) => ipcRenderer.invoke('update:check', plain(updateUrl)),
downloadUpdate: () => ipcRenderer.invoke('update:download'),
installUpdate: () => ipcRenderer.invoke('update:install'),
listUpdateVersions: (updateUrl) => ipcRenderer.invoke('update:listVersions', plain(updateUrl)),
rollbackUpdate: (updateUrl, version) =>
  ipcRenderer.invoke('update:rollback', plain(updateUrl), plain(version)),
onUpdateStatus: (handler) => { /* on + 返回 off */ }
```

### 4.5 `SettingsDialog.vue`（UI）

- 更新地址输入框（双向绑定 `updateUrl`）
- 检查更新 / 下载更新 / 安装并重启
- 回退版本 `el-select`（可手输 `x.y.z`）+ 回退并安装
- 打开设置时预拉回退列表；下拉展开时强制刷新
- 订阅 `onUpdateStatus` 刷新进度与文案

### 4.6 `App.vue`

- `loadData` 读出 `updateUrl`
- 保存配置时把 `updateUrl` 写回 AppData
- 传给设置对话框：`:update-url` / `@update:update-url`

### 4.7 打包脚本

**`scripts/pack.cjs`**

1. 尝试结束占用进程并清理 `win-unpacked`
2. 失败则换 `release-pack` / `release-pack-<ts>`
3. `npm version patch --no-git-tag-version`
4. `vite build`
5. `electron-builder --win nsis nsis-web --x64`
6. 将 `nsis-web/` 产物提升到输出根目录（保证 `latest.yml` 含 `packages`）
7. 生成 `versions.json`

**`scripts/update-versions-json.cjs`**

扫描本机各 `release*` 目录中的 `*-Setup-*.exe` 与已有 `versions.json`，合并写出当前输出目录的 `versions.json`。

## 5. 数据流

### 升级

```text
设置页「检查更新」
  → preload.checkUpdate(url)
  → main update:check
  → updater.checkForUpdates → autoUpdater（读 latest.yml）
  → update:status → UI「发现新版本」

「下载更新」
  → downloadUpdate
  → 优先差量拉 *.nsis.7z（Range）
  → update:status 进度

「安装并重启」
  → quitAndInstall
```

### 回退

```text
打开设置 / 打开「回退版本」下拉
  → listUpdateVersions
  → versions.json（若有）+ HEAD 探测 Setup-*.exe
  → 仅列出 < 当前版本

「回退并安装」
  → rollbackUpdate(url, version)
  → 下载完整 Setup → spawn(--updated) → app.quit()
```

## 6. OSS 上应放置的文件

发版后把打包输出根目录中这些文件传到同一目录：

| 文件 | 必需 | 说明 |
| --- | --- | --- |
| `latest.yml` | 是 | 须含 `packages`（nsis-web 清单） |
| `*-WebSetup-x.y.z.exe` | 是 | Web 安装器（体积小） |
| `*-x64.nsis.7z` | 是 | 差量更新主体；**勿删旧版 7z** |
| `*-Setup-x.y.z.exe` | 建议 | 离线安装、版本回退 |
| `versions.json` | 建议 | 加速回退列表；没有时客户端会 HEAD 探测 |
| `*.blockmap` | 可选 | 完整 Setup 的块图 |

`latest.yml`（web）示意：

```yaml
version: 1.0.7
path: TCP服务端数据模拟-WebSetup-1.0.7.exe
packages:
  x64:
    path: tcp-server-sim-1.0.7-x64.nsis.7z
    blockMapSize: ...
    sha512: ...
```

`versions.json` 示意：

```json
{
  "versions": [
    { "version": "1.0.7", "path": "TCP服务端数据模拟-Setup-1.0.7.exe" },
    { "version": "1.0.6", "path": "TCP服务端数据模拟-Setup-1.0.6.exe" }
  ]
}
```

## 7. 发版操作

```bash
npm run pack
```

上传输出目录中的 `latest.yml`、WebSetup、`.nsis.7z`、`versions.json`，以及完整 Setup（建议）。

客户端：设置 → 检查更新 → 下载 → 安装并重启。

说明：

- 从「完整 Setup」首次安装后的**第一次**在线更新，本地往往还没有旧 7z 缓存，下载量可能仍接近整包；之后版本间才更容易走差量。
- 回退始终下载完整 Setup，不走 7z 差量。

## 8. 踩过的坑

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| `tool//xxx.nsis.7z` 404 | `publish.url` / `appPackageUrl` 带末尾 `/`，NSIS 再拼 `/文件名` | URL **不要**末尾 `/` |
| 回退列表为空 | OSS 无 `versions.json`，且只信 `latest.yml` 当前版 | HEAD 探测历史 Setup；建议仍上传 `versions.json` |
| 打包 `app.asar` 被占用 | 程序或资源管理器锁住 `win-unpacked` | `pack.cjs` 杀进程/清理，失败则换输出目录 |
| 差量失败变整包 | OSS 不支持 multipart Range | `useMultipleRangeRequest: false` |
| 开发模式不能更新 | 未打包无安装布局 | 检查/下载/安装仅打包版；列表探测开发模式可用 |

## 9. 最小接入清单（新项目照抄）

1. 依赖：`electron-updater` + `electron-builder`
2. 复制/实现：`updater.cjs`、IPC、preload API、设置页按钮
3. `package.json`：`publish` + `nsis` + `nsisWeb`（URL 无尾斜杠）
4. 打包脚本：同时打 nsis / nsis-web，并提升 web 的 `latest.yml`
5. OSS：上传 `latest.yml`、WebSetup、`.nsis.7z`（及旧 7z）、可选 Setup / `versions.json`
6. 验证：打包安装 → 改小版本号再打一包上传 → 客户端检查更新应走差量或完整下载成功
